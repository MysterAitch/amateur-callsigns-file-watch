layer anatomy · G0TQK

Why keying off the raw bytes recovers what the tidy file loses

In the 2019 register, G0TQK appears twice — once as itself, once with an invisible trailing non-breaking space. Two distinct raw tokens; both normalise to the same entity. The current normalised CSV keeps both rows but shows both as clean G0TQK — you can no longer tell which was damaged. The ledger keeps the raw token, the rule, and the attributes together, so nothing is quietly lost.

Both observations are real and co-temporal. The entity view shows both, with provenance — it never silently picks a winner. That is the join key obeying transparency-first.

One licence type, many spellings — search the canonical form

Every node carries a normalised form, always (identity when already clean), so a query never has to ask which form to use. Licence type works exactly like the callsign: fifteen raw spellings across nine years collapse to a handful of canonical types. Pick one to see the raw spellings it unifies and a few callsigns holding it in the latest snapshot.
