Join keys and semantics

Join keys: callsign joins everything — the latest database's normalised ↔ components tables, and the master database's register_history (one row per callsign per publication, keyed by dataset) ↔ observations (one row per FOI-witnessed assertion, keyed by entry).

NULL vs empty string (master observations): NULL means the source dataset never asserted that column; '' means the source asserted a blank value. The distinction is the point — a blank status in the 2019 register is data.

Absence is not evidence: publications vary in scope (history_datasets carries each one's record count and declared coverage) — a callsign missing from a declared-partial publication tells you nothing, and even declared-complete exports have been observed silently filtering records.

The cleaned join key (on components, register_history and observations) unifies publisher artefacts — uppercase, stripped outside A–Z/0–9// — so longitudinal joins survive whitespace and encoding damage. Duplicates are expected and deliberate: it is a join key, never an identity.

A cohort worth reproducing (heavy — run it on the downloaded master database, not here): forbidden-suffix callsigns in the current register that were absent from the August 2019 FOI snapshot — the "issued after the withheld list existed" candidates (each needs per-member checking: artefact fixes and heritage re-issues are innocent explanations):

SELECT rh.callsign, rh.status, rh.licence_version_original_start_date
FROM register_history rh
JOIN ref_forbidden_suffixes f ON f.suffix = rh.suffix
WHERE rh.dataset = '2026-06-23'
  AND rh.cleaned NOT IN (
    SELECT cleaned FROM observations
    WHERE entry = 'wdtk-596532--allocated-reserved-forbidden')
ORDER BY rh.licence_version_original_start_date;
