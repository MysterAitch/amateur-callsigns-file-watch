callsign-record / get the raw data

Every archived publication, preserved byte-for-byte in the open repository, with the code that builds the databases from it.

The mirror preserves each publication exactly as published. Nothing is derived beyond what the sources state; every derived database carries provenance to the byte. The archived files and the code that folds them – the build step that assembles each database from the raw files – are in the public repository on GitHub; each repository link below opens in a new tab. The databases, the per-publication downloads, and the claim ledger are built and published with each build of this site, but are not linked from these pages yet: each is listed below, marked as such, with where its builder lives.

browse the archive

The archive, in the repository

Every archived dataset in both collections, Ofcom open-data publications and FOI requests, with its files preserved verbatim. Extract and normalised files sit beside the raw files where they were derived and committed; not every entry has them, and an FOI entry may hold its correspondence with no data at all. Each entry carries its meta.json, which records a sha256 for every file, and each FOI entry its correspondence.md. The files can be fetched one at a time from there.

per-entry: raw files · meta.json · correspondence (FOI) · derived files where committed

Reference data & schemas

The vocabularies and schemas that make the published datasets interpretable without the repository – prefix formats, licence categories, the forbidden-suffix union and the flag registry – each documented alongside the data.

built downloads

The combined SQLite database and the FOI observations union

One SQLite database of everything – the FOI observations union plus every open-data publication’s normalised rows – and the flat union CSV. Both are built from the archive by the download builder in the repository, so they can be rebuilt from the archived files.

Per-publication SQLite databases and zips

For each archived publication, one SQLite database with a table per CSV, and one zip of the entry’s files with its Frictionless datapackage.json descriptor. Both are built at publish time, by the download builder and the per-entry builder; the datapackage.json descriptors are not committed to the repository. Until they are linked here, an entry’s own files can be fetched one at a time from the archive above.

The folding code

Every derived database is a deterministic projection of the archived bytes – a rebuild from the raw files, never a re-interpretation of them. The code that reads the archive and folds each tier is in the repository, so any derived value can be reproduced from the raw files.

the claim ledger & provenance

The raw-keyed claim ledger

Every value the mirror derives traces to the source byte that asserts it – one record per raw byte, every derivation rule and every source row behind a value. The ledger is built at publish time and is not committed to the repository; its builder is. The ledger database and a page for querying it are published with each build of this site, but neither is linked from these pages yet.

What is held, how it is folded, and the integrity record for every publication – all in the open, versioned repository this mirror is built from.

licensing & attribution

This project’s own code and original documentation are released under the MIT licence. The data it mirrors is not covered by that licence: every archived file is reproduced from its publisher under that publisher’s own terms – see archive/LICENSE.md for how that applies, and each publisher’s statement and verification links in the repository.

An independent, unofficial mirror, not affiliated with or endorsed by Ofcom. Data belongs to its original publishers; provenance and integrity hashes accompany every file.
