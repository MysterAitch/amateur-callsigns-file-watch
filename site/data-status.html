Data status

A build-time-derived tracker of every dataset this mirror holds or knows exists, and how far each has been carried through the processing pipeline. It doubles as the work-queue — what to process next — and the gap-finder. Nothing here is hand-maintained: every row and cell is computed on each deploy from the committed archive, each entry's meta.json, and the source register, so it cannot drift from reality. This page is fully static (no scripts), so archived captures of it are complete.

This is axis 1 of three — the processing view

Three separate questions, deliberately not conflated:

  1. Processing (this page) — how far a file has been carried through the pipeline. Operational, like build tasks.
  2. Source authority — how trustworthy the origin is (Official → FOI → Reference → Community → Self), from each entry's meta.json. Shown here only as the small “Source” tag, for orientation.
  3. Claim confidence — how much to trust a given fact (As-published → Computed → Looked-up → Community → Best-guess), the tiered claim layer surfaced on the Ledger.

A high-authority source can still yield a low-confidence claim, which is why the three are kept apart. The three axes are defined in full in the glossary.

Datasets grouped into series over time, so coverage, staleness and gaps are visible. A long silence between consecutive held vintages is flagged with a plain next-step — no action is automated; the gap is surfaced and the option named.
